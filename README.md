# 投票登记与实时统计系统

这是一个用于现场人员确认、投票登记和分组统计的开源示例项目。

公开仓库只包含虚构的示例人员数据。真实姓名、身份证号、电话、地址和现场记录不应提交到 GitHub。

## 它解决什么问题

现场投票经常分布在多个投票点：一个点登记后，其他点看不到最新进度，负责人还要靠电话、纸张或多个 Excel 手工汇总。本系统把人员名单、投票状态和统计集中到同一个服务中：

- **多个投票点实时共享**：不同电脑或手机访问同一服务后，某个投票点登记的结果会同步到其他设备，现场负责人可以直接看到整体进度。
- **减少重复登记和人工汇总**：同一人员只能成功登记一次，系统自动计算已投票、未投票和投票率。
- **现场查找更快**：按投票点、分组、姓名、地址、电话或备注查找，适合工作人员边核对边登记。
- **有记录、可纠错**：保存操作员和时间，误点可以撤销；发生并发操作时由服务端判断最终状态。
- **支持真实名单导入**：电脑端下载标准 Excel 模板，按格式填写后预览并导入，开始新一轮投票时会清空上一轮状态，避免串场。
- **开源示例不暴露真实数据**：公开仓库只保留虚构样例；客户数据保存在本地运行文件中，不会随代码提交。

## 功能

- 按投票点和分组查找人员。
- 搜索姓名、地址、身份证号、电话和备注。
- 登记投票、撤销误操作并防止重复登记。
- 实时统计总人数、已投票、未投票和投票率。
- 电脑端导入标准 Excel 人员名单。
- 手机端和电脑端均可使用，Excel 导入按钮仅在电脑端显示。

## 本地启动

在公开仓库目录执行：

```bash
npm install
npm run start:demo
```

看到终端出现“投票系统已启动”后，再打开 <http://localhost:8787>；如果 `localhost` 无法打开，请改用 <http://127.0.0.1:8787>。启动终端必须保持运行。

如果只执行 `npm start`，则需要先配置操作员密码；本地演示建议使用上面的 `npm run start:demo`。首次启动会从示例文件创建本地数据文件。

### 启动故障排查

- `Cannot find module`：确认当前目录是本仓库，并重新执行 `npm install`。
- `EADDRINUSE` 或端口被占用：换一个端口，例如 `PORT=8788 npm run start:demo`，然后打开 <http://127.0.0.1:8788>。
- 其他手机或电脑访问时，不能使用它们自己的 `localhost`；应访问运行服务那台电脑的局域网 IP 和端口，并确保设备在同一网络。
- 可以用 `curl -I http://127.0.0.1:8787` 检查服务是否真的已监听。

示例账号使用 `wlx`，示例密码也是 `wlx`。这只适用于本地演示。正式使用时必须配置独立密码：

```bash
OPERATOR_wlx_PASSWORD='请替换为强密码' \
OPERATOR_ydn_PASSWORD='请替换为强密码' \
npm start
```

首次启动会从 `data/people.example.json` 创建本地数据文件 `data/people.local.json`。该文件已加入 `.gitignore`，客户导入的真实数据不会被 Git 跟踪。

## Excel 导入

电脑端登录后，点击“下载导入模板”取得标准文件，再点击“导入 Excel”。系统会先检查并预览数据，确认后才会替换人员名单。

模板的第一张表必须叫“人员数据”，第一行表头不要改名。必填列是：

```text
编号、投票点、分组、地址、姓名
```

可选列是：

```text
身份证号、电话、备注
```

确认导入后，当前人员名单会被替换，当前投票状态和操作记录会清空。这是为了避免新一轮投票沿用上一轮状态。导入前请备份 `data/people.local.json`。

Excel 导入功能依赖本地 Node.js 服务端写入数据文件。部署到 Vercel 的示例 API 不提供文件导入能力，需要另行接入数据库中的人员表。

## 隐私和安全

- 不要提交真实人员 Excel、`data/people.local.json`、`runtime/state.json`、截图或导出文件。
- 不要把 Supabase 密钥、会话密钥或生产密码写入源码。
- 对外演示请使用独立的示例数据和独立的数据库项目。
- 这个系统是现场辅助登记工具，不是匿名电子投票系统，也不替代正式的身份认证和选举流程。
